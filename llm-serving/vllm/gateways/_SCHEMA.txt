====================================================================
 게이트웨이 yaml 키 레퍼런스
====================================================================

gateways/<port>.yaml 1개 = vLLM 게이트웨이 1대. 이 문서는 모든 게이트웨이
yaml이 공유하는 키 설명이다. yaml에는 키당 제목 한 줄 주석만 두고, 상세는
여기를 본다.

[복붙 규칙] 게이트웨이를 추가할 땐 기존 yaml을 복사해 gateway.host /
gateway.port만 바꾼다. 주석은 모든 파일에서 동일하므로 손대지 않는다. 파일
구분은 파일명(<port>.yaml)과 값으로만 한다.


── 동작 개요 ────────────────────────────────────────────────────────

  - 자동 디스커버리: discover_from 디렉토리(../instances)의 *.yaml 중
    gateway_port가 이 게이트웨이 포트와 같은 인스턴스를 backends로 자동
    등록한다. 매칭 결과는 기동 로그에서 확인할 수 있다.
  - 로드밸런싱: 같은 gateway_port를 갖는 인스턴스 yaml을 instances/에
    추가하면, 게이트웨이 재기동 시 자동으로 backends에 포함되어 LB된다.
  - 수동 backends 우선: yaml에 backends를 직접 명시하면 디스커버리보다
    우선한다.


── gateway — 게이트웨이 서버 ────────────────────────────────────────

  host
      바인딩 주소. 외부 접속 허용은 0.0.0.0, 로컬 전용은 127.0.0.1.
      PII 프록시 뒤에 두는 내부 게이트웨이는 127.0.0.1 (프록시 우회 경로 차단).
  port
      클라이언트(또는 PII 프록시)가 접속하는 포트. 방화벽/보안그룹 오픈 대상.
  log_level
      로그 레벨. 일반 운영 info, 상세 진단 debug.


── discover_from — 백엔드 디스커버리 ────────────────────────────────

이 파일 기준 상대 경로. gateway_port가 이 게이트웨이 포트와 같은
instances/*.yaml만 백엔드로 자동 등록한다.


── health_check — 헬스체크 ──────────────────────────────────────────

  interval_seconds       백엔드 /health 확인 주기(초).
  timeout_seconds        /health 요청 1회 타임아웃(초).
  unhealthy_threshold    연속 실패가 이 값에 도달하면 unhealthy로 전환.
  healthy_threshold      unhealthy 상태에서 연속 성공이 이 값에 도달하면
                         healthy로 복구.


── warmup — 서버 웜업 (CUDA 예열) ───────────────────────────────────

  enabled
      시작/복구 시 더미 추론으로 CUDA 커널을 예열할지 여부.
  boot_poll.interval_seconds
      백엔드가 /health를 반환할 때까지 재시도하는 간격(초).
  boot_poll.timeout_seconds
      모델 로딩을 포함한 백엔드 기동 대기 상한(초).
  inference.prompt
      예열용 더미 프롬프트. 운영 응답에는 노출되지 않는다.
  inference.max_tokens
      예열 추론의 최대 생성 토큰 수.
  inference.timeout_seconds
      예열 추론 요청 타임아웃(초).


── prefix_cache_warmup — 프리픽스 캐시 웜업 ─────────────────────────

공통 시스템 프롬프트를 미리 넣어 KV 캐시 적중률을 높인다.

  enabled
      프리픽스 캐시 웜업 여부.
  max_tokens
      캐시 적재 확인용 생성 토큰 수. 보통 1이면 충분.
  timeout_seconds
      프리픽스 캐시 웜업 요청 타임아웃(초).
  system_prompt
      서비스 공통 시스템 프롬프트. 변경 시 재시작 후 재웜업된다.


── backend_api_key — 백엔드 인증 (선택) ─────────────────────────────

vLLM --api-key 사용 시 게이트웨이의 내부 웜업 요청에 쓸 키. 기본은 주석
처리(미사용).


── http_client — HTTP 클라이언트 ────────────────────────────────────

  timeout_seconds
      백엔드 추론 요청 전체 타임아웃(초). 긴 답변을 고려해 넉넉히.
  connect_timeout_seconds
      백엔드 TCP 연결 수립 타임아웃(초).
  max_connections
      백엔드 연결 풀 상한. 실제 동시 추론 제한은 overload가 담당한다.


── overload — 과부하 차단 ───────────────────────────────────────────

chat/completions 요청에 동시 처리량과 대기열 제한을 적용한다.

  enabled
      과부하 차단 적용 여부.
  max_inflight_requests
      백엔드 vLLM으로 즉시 넘길 최대 요청 수. 단일 vLLM max_num_seqs
      이하 권장.
  max_queue_size
      동시 처리 한도 초과 시 게이트웨이에 대기시킬 최대 요청 수.
  queue_timeout_seconds
      대기열에서 슬롯을 기다릴 최대 시간(초). 초과 시 429 queue_timeout.
  retry_after_seconds
      429 응답의 Retry-After 헤더 값(초).


── compat — 모델 교체 호환 계층 ─────────────────────────────────────

클라이언트가 보는 모델명을 하나로 고정한 채(인스턴스 yaml의
served_model_name) 뒤에서 Gemma/Qwen/GLM을 갈아끼우기 위한 계층이다.
모델마다 다른 요청 파라미터를 게이트웨이가 흡수해 클라이언트가 400/422를
보지 않게 한다. 세 스위치 모두 기본 활성이라 yaml에 없어도 동작한다.

  translate_reasoning_effort
      reasoning_effort를 백엔드가 아는 값으로 번역한다. 클라이언트는 OpenAI
      표준값(minimal/low/medium/high)을 그대로 보내면 되고, 백엔드가 그 값을
      모르면 필드가 제거되어 200으로 응답한다. 적용 결과는 응답 헤더
      X-Effort-Applied와 게이트웨이 로그에 남는다.
      추론 켜고 끄기(2026-10-10~): 기본은 인스턴스 설정(꺼짐)을 따르고, effort를
      주면 추론을 켠다. 클라이언트가 enable_thinking을 직접 보냈으면 그 값을
      따르고, effort none은 언제나 끈다. 스펙 밖 문자열은 추론을 켜지 않는다.
      게이트웨이가 enable_thinking을 명시하고 effort는 chat_template_kwargs로
      넘긴다. vLLM 0.31의 최상위 effort 자동 처리(0.31.0
      entrypoints/openai/chat_completion/protocol.py:585-586)는 옛 nightly에 없어
      거기에 맡기면 버전마다 동작이 달라지기 때문이다.
      끄면 클라이언트 값이 백엔드로 그대로 전달된다 — Qwen3.8에 high를 보내면
      HTTP 400이 난다.
  mask_model_path
      GET /v1/models 응답의 root(실제 체크포인트 경로)를 id(별칭)로 덮는다.
      served_model_name은 id만 바꾸고 root에는 실경로가 남기 때문에, 클라이언트가
      보는 모델 식별자를 id 하나로 통일하려면 이것도 필요하다.
      운영자가 실제 체크포인트를 확인할 때는 백엔드 vLLM 포트를 직접 조회한다.
  effort_profiles
      모델 계열별 effort 번역표. 키는 root 경로에 대한 부분 문자열(대소문자
      무시), 값은 {클라이언트 값: 백엔드 값}이다. 비우면 코드 기본값
      (_DEFAULT_EFFORT_PROFILES — 현재 qwen3.8만 등록)을 쓴다.
      새 모델이 effort를 지원하면 여기에 항목을 추가한다. 등록되지 않은 계열은
      effort 미지원으로 보고 필드를 제거한다.
  inject_identity_prompt
      /v1/chat/completions의 messages 맨 앞에 정체성 시스템 프롬프트를 얹는다.
      모델의 자기소개는 사후 학습으로 가중치에 박혀 서빙 설정으로는 못 바꾸므로,
      기반 모델을 밝히지 않게 하려면 프롬프트로 지시해야 한다.
      클라이언트 system 메시지가 있으면 그 안으로 병합한다(정체성 문구가 앞).
      새 system 메시지를 index 0에 끼우면 Qwen3.8 템플릿이 400을 내기 때문이다.
      끄면 모델이 학습 때 이름으로 자기소개한다.
  identity_prompt
      주입할 문구. 비우면 코드 기본값(_DEFAULT_IDENTITY_PROMPT — 기반 모델을
      밝히지 않고 "이 서비스의 AI 어시스턴트"라고만 답하게 하는 영어 문구)을
      쓴다. 백엔드를 무엇으로 바꾸든 이 문구는 그대로 간다(계열별 분기 없음).
      기본값이 어느 계열에서도 참인 문구이므로 보통은 비워 둔다.
