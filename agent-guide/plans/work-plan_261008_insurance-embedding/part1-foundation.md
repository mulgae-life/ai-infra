## 작업 목록

### P0 준비

- [ ] 결정 요청서 작성: master "결정 요청" 표의 5건. 항목마다 묻는 것, 추천안, 담당, 필요 시점, 없을 때 진행 범위
- [ ] 결정 1번 근거 정리(기술 담당): 설계 3.1절 원천별 이용 조건 원문, 우체국 API 활용신청 절차, 일반 평가 과제 후보와 E0 후보 모델의 이용 조건
- [ ] 착수 직전 실측 항목 목록: GPU별 메모리·사용률·프로세스, 디스크 여유, :5015 상태

### P1 기반·평가기

- [ ] **학습 환경**: 서빙 환경과 분리한다. 비교 기간에는 버전을 고정한다. 가상환경을 git에서 제외한다
- [ ] **원천 목록**: 설계 3.1절 원천 전부, 일반 평가 과제 후보, E0 후보 모델. 각 항목의 용도별(개발·평가·학습) 허용 상태와 근거, 확인일
- [ ] **공통 기반**
  - 권리 게이트: 용도를 밝히고 요청해야 파일을 읽을 수 있고, 미정·제외는 막는다
  - 버전 기록: 새 번호로만 쓰고 덮어쓰지 않는다. 버전마다 입력 버전, 설정, 코드 커밋, 행 수, 권리 필터를 남긴다
  - 행 형식: 원천 파일, 청크, 질의, 정답(관련도·근거 묶음), 학습 쌍
- [ ] **평가기**
  - 관련도 0/1/2와 이득 `2^관련도 − 1`인 등급 nDCG, 관련도 2 기준 Recall, 필수 근거 묶음 완전 회수율
  - 답 없음·조건 부족 지표: 잘못 통과율, 추가 질문 판정률, 정상 질의 불필요 보류율
  - 두 평가 과제와 질의 출처를 나눠 보고하고, 군집 단위 짝지은 부트스트랩을 계산한다
  - 시험셋은 `--final`로만 열리고, 열 때마다 기록한다
- [ ] **직접 쓴 예문 세트**: 약관 문체로 직접 쓴 문장. 숫자·기간·부정 조건, 표 머리글, 준용 조항, 다중 정답, 답 없음, 조건 부족을 담는다. 흐름과 지표를 확인하는 용도이고, 보험 정확도 평가 자료로 보고하지 않는다

## 산출물 형태 (예시)

**결정 요청서 한 행**

| 결정 | 묻는 것 | 추천 | 담당 | 필요 시점 | 없을 때 |
|------|---------|------|------|-----------|---------|
| 첫 자료 범위 | 우체국보험 약관 몇 건을 파서 개발용으로 로컬에서만 써도 되는가 | 개발용만 허용, 평가·학습은 별도 판단 | 권리 담당 | P2 전 | P1까지만 진행 |

원천 목록은 원천마다 용도별(개발·평가·학습) 허용 상태, 근거, 확인일을 기록한다. 필드 구성은 P1 착수 때 정한다.

## 검증

- 권리 게이트: 미정·제외 자료, 허용되지 않은 용도의 요청이 거부되는 시험
- 버전 기록: 같은 번호에 다시 쓰면 실패하는 시험
- 평가기: 직접 쓴 예문의 순위 결과로 손계산한 값과 지표가 일치하는 시험. 관련도 1·2가 섞인 경우, 답 없음 질의, 근거 묶음 일부만 찾은 경우를 포함
- 시험셋 봉인: `--final` 없이 열면 실패하고, 열면 기록이 남는지 확인
- 환경 분리: 학습 환경을 만든 뒤에도 서빙 환경의 패키지 목록이 그대로인지 확인
