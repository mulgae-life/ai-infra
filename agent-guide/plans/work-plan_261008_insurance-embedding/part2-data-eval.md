# Part 2: 실제 원문, 평가셋, E0 — P2-P4

> master: [master.md](master.md)
> 선행 Part: [part1](part1-foundation.md) | 후속 Part: [part3](part3-training.md)
> 담당 Phase: P2-P4 | 상태: 초안

## 목표

- 허용된 실제 약관을 원문 위치를 잃지 않고 청크로 바꾼다. 개발셋 초기 정답을 만든다.
- 기성 모델을 같은 조건에서 비교해, 학습이 필요한지 판단한다.

## 전제 조건

- [ ] part1 완료: 권리 게이트, 버전 기록, 평가기가 검증을 통과
- [ ] P2 전: 결정 1번 중 개발 표본 허용. 개발용 허용은 그 용도에만 적용되고, 평가·학습으로 쓰려면 별도로 확인한다
- [ ] P2 검수 전: 결정 2번 중 핵심 조건 대조 담당, 결정 4번(판정 백업). 없으면 원문 추출 준비까지만 하고 의미 검수를 통과했다고 표시하지 않는다
- [ ] P3 전: 결정 2번 중 질의 작성·주석 인력. 해당 자료의 평가 이용 범위
- [ ] P4 전: 결정 3번 중 E0 동시 사용 한도. 비교 대상 모델의 이용 조건

## 작업 목록

### P2 실제 원문

- [ ] 허용된 표본 수집. 파일마다 설계 3.2절의 기록(출처, 상품, 시행 기간, 해시, 권리 근거, 수집일)
- [ ] 파싱. 일반 추출과 정렬 추출을 비교하고, 표·다단·문자 위치를 확인한다. 복원할 수 없는 영역만 문자 인식(OCR)으로 처리하거나 제외한 뒤 원문 화면과 대조한다
  - 음절 순서 문제(배치 순서)와 문자 해석 실패(글꼴 문자 대응, 이미지 글자)를 구분해 기록한다
  - 표는 머리글·단위를 보존한다. 여러 페이지에 걸친 표와 준용 관계는 자동 결과를 그대로 믿지 않는다
- [ ] 청크 규칙 v1(보험 연구용). 문서 구조(보통약관·특약·조·항·호·별표) 기준으로 자르고, 맥락 헤더(상품·특약·시행일·조 제목)를 붙인다. 원문 페이지와 연결한다. 규칙에 버전을 붙인다
- [ ] 동등 조항 묶기. 조 번호가 아니라 내용으로 묶는다. 같은 제목이라고 모두 묶지 않는다
- [ ] 사내 문서가 들어오면 개인정보를 가린다
- [ ] 결과 기록: 표본 범위, 훼손률, 제외한 자료와 그 이유. 중요한 표·별표가 대거 빠지면 복원할지 평가 범위를 줄일지 판단한다. 사람이 대조한 검수 기록은 남길 때마다 백업한다

### P3 초기 주석

- [ ] 분할. 두 평가 과제의 규칙을 따로 적용한다. 시험 계열을 먼저 떼어 봉인한다
  - 같은 문서의 새 질의: 문서 공유를 허용하고, 질의와 그 바꿔 쓴 질의를 한쪽에 둔다
  - 새 문서: 상품·개정 계열과 동등 조항군까지 학습·개발·시험 사이에서 나눈다. 시험 문서로는 합성 질의를 만들지 않는다
- [ ] 판정지. 스프레드시트로 내보내고 받는다. 받을 때 형식·필수 칸·관련도 값을 검증한다
- [ ] 50개 시범. 관련도 0/1/2, 필수 근거 묶음, 답 없음·조건 부족 기준을 실제 표본에 적용해 주석 기준을 다듬는다
- [ ] 개발 200개 초기 정답. 핵심 조건 질의는 2인 검토. 질의 출처(실제 로그 / 전문가 작성 / LLM 초안 후 수정)를 기록한다
- [ ] 사람 판정은 받을 때마다 백업한다

### P4 E0 기준선

- [ ] 착수 직전 GPU 재실측 → 한도 안에서 소량 인코딩으로 메모리와 다른 작업 영향을 확인한다. 한도를 넘으면 시간대를 나눈다
- [ ] 후보 목록 고정. KURE-v1, Snowflake-ko, Qwen3-Embedding-0.6B, BGE-M3, PIXIE-Rune-v1.5, 그리고 지금 쓰는 보험 검색기가 있으면 그것도 넣는다. 뺀 후보는 이유를 공개한다
- [ ] 검색 대상 고정. 승인된 연구 범위의 전체 후보 말뭉치(목록·버전·규모)와 상품·시행일·권한 필터 조건을 정한다. 상품·시행일이 불분명한 질의는 필터값을 임의로 채우지 않고 조건 부족으로 둔다. 파싱용 소량 표본에서만 비교했다면 예비 결과로 표시한다
- [ ] 모델별 입력 형식 기록. 질의·문서 프롬프트(예: Snowflake-ko는 `query: `), 풀링·정규화, 최대 길이. 모델별 토크나이저로 근거 잘림 비율을 잰다(512·1024, 필요하면 1300)
- [ ] 판정 풀. BM25, 후보 모델, 하이브리드의 상위 k를 합쳐 판정할 대상을 정한다. 판정 풀로 검색 대상을 줄이지 않는다. 미판정 문서는 모델명을 가리고 추가 판정한 뒤 공통 정답표 새 버전으로 전부 다시 계산한다
- [ ] 상위 후보에 맥락 헤더 유무와 어휘 검색 결합을 비교한다
- [ ] 거짓 네거티브 진단. 개발 질의 100개, 이미 알려진 정답을 뺀 상위 후보 최대 10개씩, 최대 1,000쌍을 사람이 판정한다(유효 네거티브 / 추가 정답 / 보류)
- [ ] 오류 분류와 학습 필요성 판단. 현업이 중요하게 보는 오류가 기성 구성으로 해결되는지 본다. 업무 목표가 정해지지 않았으면 "학습 불필요"로 단정하지 않고 판단 보류 사유와 선택지를 보고한다

## 산출물 형태 (예시)

**E0 비교표 한 행**

| 모델 | 맥락 헤더 | 어휘 결합 | nDCG@10 (등급) | Recall@10 (관련도 2) | 묶음 완전 회수 | 근거 잘림 | 판정률(상위 10) |
|------|-----------|-----------|----------------|----------------------|----------------|-----------|-----------------|
| (후보) | 있음 | 없음 | 값 ± 신뢰구간 | 값 | 값 | 비율 | 비율 |

두 평가 과제는 표를 따로 만든다. 합산하지 않는다.

## 검증

- 원문 품질: 파싱 표본을 원문 화면과 대조. 금액·기간·부정·준용 조건 훼손 여부
- 누설: 같은 문서 과제는 같은 질의군이, 새 문서 과제는 같은 계열·동등 조항군이 개발·시험에 걸쳐 있지 않은지 검사
- 판정지: 받은 파일의 형식 오류가 거부되는지, 백업본에서 복구되는지 확인
- E0: 모든 후보를 같은 공통 정답표, 고정한 후보 말뭉치·필터, 같은 평가 조건으로 계산했는지 확인. 답 없음·조건 부족의 판단 기준(임계값)을 개발셋에서 정해 기록한다

- [ ] 코덱스 검수: 분할 누설, 판정 풀 처리, E0 해석
