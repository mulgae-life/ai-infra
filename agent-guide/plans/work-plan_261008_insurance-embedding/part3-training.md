## 작업 목록

### P5 학습 준비

- [ ] 합성 지시문. 정답 청크는 고정하고 질의만 만든다. 질문자 역할(고객·설계사·상담원·보상 담당·언더라이터)과 질의 형태·길이를 바꿔 다양성을 준다. 개발·시험 질의는 예시로 쓰지 않는다
- [ ] 100문항으로 처리량을 잰다. 생성 시도 수가 아니라 검수 후 채택된 쌍 수로 계산한다. :5015 동시 요청은 합의한 한도 안에서만
- [ ] 300개 표본 검수(유형별 층화). 근거 일치율 95%는 제안 문턱이다. 면책·금액·기간·부정 조건 오류는 통과 여부와 별개로 고쳐 다시 검수한다. 미달이면 생성량을 늘리지 않고 파싱·지시문부터 고친다
- [ ] 기반 모델이 원 청크를 못 찾는 질의는 바로 버리지 않는다. 생성 오류인지, 학습으로 메울 어려운 질의인지 나눈다
- [ ] 학습셋 조립. 일반 데이터의 학습 권리가 확인되면 보험 합성 8천 + 일반 2천, 아니면 보험 합성 1만. 일반 데이터는 이 합성 절차로 만들지 않는다. 학습 분할에서만 만든다
- [ ] 동등 조항 충돌 관리. 같은 묶음의 조항이 네거티브를 공유하는 한 대조 배치에 같이 들어가지 않게 한다
- [ ] 학습셋 이력 기록. 한 행에서 원본 파일과 권리 근거까지 거슬러 올라갈 수 있게 한다
- 명시적 하드 네거티브 채굴은 하지 않는다(E2 준비)

### P6 E1 첫 학습

- [ ] 착수 직전 GPU·디스크 재실측, 배정 시간대 확인
- [ ] 학습량은 설계 6.3절의 초기 설정(최대 2에폭) 안에서 정한다. 그 계획한 단계 중 처음 최대 100단계로 메모리와 단계 시간을 잰다. 별도 시험 학습을 따로 돌리지 않는다. 준비·예열·인코딩·평가 시간을 나눠 기록한다
- [ ] 같은 기반 모델, 기본 대조 손실(`CachedMultipleNegativesRankingLoss`, 손실을 반드시 명시), 배치 내 네거티브만. 학습률 1e-5와 2e-5 두 가지
- [ ] 반 에폭마다 개발셋으로 평가한다. 시험셋으로 체크포인트를 고르지 않는다. 실행당 체크포인트 개수를 제한한다
- [ ] 일반 한국어 검색 과제로 학습 전후를 비교한다. 이용 조건이 미해결이면 일반 성능 판단을 보류하고, 평가 없이 "보존"으로 보고하지 않는다
- [ ] 7.3절 기준으로 판정한다
  - 같은 기반 대비: nDCG@10 절대 +0.03 이상, 짝지은 군집 부트스트랩 95% 신뢰구간 하한 > 0, Recall@10 비하락, 핵심 조건 하위군 2%p 넘는 하락 금지
  - 일반 성능: 평균 하락 1점 이내
  - 답 없음·조건 부족: E0에서 정한 판단 기준으로 잘못 통과율, 추가 질문 판정률, 정상 질의 불필요 보류율
  - 지연: 같은 조건에서 질의 지연 95백분위와 기반 대비 비율(1.2배 이내). 공유 부하 때문에 비교가 성립하지 않으면 지연 판정은 보류
  - 최적 기성 구성(맥락 헤더·어휘 결합 포함) 대비 가치는 따로 보고
- [ ] 결론은 "개발셋에서 후속 검증 가치 있음" 또는 "원인 진단 후 재검토"로 쓴다. "실험 완료"와 "품질 기준 충족"을 나눠 기록한다
- [ ] 두 학습률 모두 개선이 없으면 규모를 늘리지 않고 파싱·주석·누설·거짓 네거티브·필터를 다시 본다

## 검증

- 합성 품질: 300개 표본의 근거 일치율과 오류 유형별 건수
- 누설: 학습셋에 개발·시험 질의군이 없는지 검사. 새 문서 과제의 개발·시험 계열·동등 조항군 문서는 학습셋에 없는지 검사(같은 문서 과제의 문서 공유는 허용)
- 배치 충돌: 같은 동등 조항 묶음이 한 대조 배치에 들어가지 않았는지 검사
- 판정: E0와 같은 공통 정답표·평가 조건으로 계산했는지 확인
